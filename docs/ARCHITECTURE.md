# 架构与数据流

## 边界

工程分为三个稳定边界：

1. React/TypeScript 负责队列状态、画布选区、设置和本地导出合成。
2. Tauri 命令层负责输入校验和前后端数据契约。
3. Rust 核心负责文件导入、PDF 转页、隐私图生成、Images API 请求和本机凭据存储。

Rust 模块职责：

- `domain.rs`：跨边界 DTO 和归一化坐标
- `importer.rs`：图片/文件夹扫描、PDF 转页、预览编码
- `privacy.rs`：隐私像素移除与编辑 alpha mask
- `openai.rs`：Images API multipart 客户端与错误归一化
- `credentials.rs`：API Key 私有文件存储与旧 Keychain 迁移
- `pipeline.rs`：单页处理编排与导出写盘
- `commands.rs`：最薄的 Tauri IPC 入口

## 单页流程

```text
原始页面
  -> 应用隐私遮挡区，生成不会包含原始敏感像素的请求图
  -> 可选：把文字编辑范围转换成 alpha mask
  -> POST /v1/images/edits
  -> 返回完整翻译页
  -> 本机按归一化坐标回填文字区与隐私区
  -> 在回填边缘环带执行局部泊松融合，核心区域保持原始像素
  -> PNG 导出
```

不创建文字编辑范围时，模型处理整页。创建文字编辑范围后，透明区域表示可编辑，其他像素保持不变。隐私范围与文字范围重叠时，隐私优先，并在编辑 mask 中保持不透明。

## 并发模型

批处理使用固定 worker 池，并发上限为 8，避免一次导入大量页面时无界创建网络请求。“处理当前页”不进入 worker 池：每次点击为所选页面创建独立任务并立即调用 Tauri 命令，因此用户可以逐页连续提交任意数量的并发请求。同一页面只允许一个在途任务，避免重复点击造成结果竞态。

每个任务拥有独立 job ID、取消令牌和临时目录。顶部“中断任务”会枚举并取消当前全部批处理和逐页任务；已经完成的页面不会回退。

## 扩展点

- 新输入格式：在 `importer.rs` 中增加规范化为页面 PNG 的适配器
- 新图像提供方：实现与 `OpenAiClient::edit_image` 等价的客户端并在管线选择
- 新导出格式：复用前端 `renderPageToPng` 生成的最终像素，再增加编码器
- 持久项目：将 `PageItem`、归一化范围和设置序列化；不保存 API Key

## 隐私保证边界

隐私遮挡只保证被覆盖区域的原始像素不会进入应用发出的图像请求。未画入隐私范围的页面像素会上传。生成模型仍可能拒绝请求或改变非文字内容；应用不会尝试绕过服务安全策略。
